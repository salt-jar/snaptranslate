# Code of Conduct / 行为准则

This project follows a simple rule: **be respectful, be constructive, and assume good
intent**. We want contributors with different backgrounds, languages, and skill levels to
feel safe here. This document is adapted from the
[Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).

本项目遵循一条简单原则：**保持尊重、建设性，并默认对方是善意的。**
我们希望不同背景、语言和水平的贡献者都能在这里安心参与。
本准则改编自 [Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/)。

## Our pledge / 我们的承诺

We pledge to make participation in this project a harassment-free experience for everyone,
regardless of age, body size, visible or invisible disability, ethnicity, sex
characteristics, gender identity and expression, level of experience, education,
socio-economic status, nationality, personal appearance, race, religion, or sexual identity
and orientation.

我们承诺：无论年龄、体型、可见或不可见的残障、民族、性别特征、性别认同与表达、
经验水平、教育程度、社会经济状况、国籍、外貌、种族、宗教或性取向如何，
参与本项目都不会受到骚扰。

## Expected behavior / 期望行为

- Be kind and patient, especially with people using a second language.
- Give actionable feedback about code, not about people.
- Respect differing opinions and accept that maintainers make the final call on scope.
- Credit other people's work and ideas.
- Redact API keys, tokens, personal data, and screenshots containing private information.

- 友善、耐心，尤其对使用第二语言交流的人。
- 对代码提出可执行的建议，而不是攻击个人。
- 尊重不同意见，并理解维护者会对范围做最终决定。
- 注明他人的工作和想法。
- 打码 API Key、令牌、个人数据以及包含隐私信息的截图。

## Unacceptable behavior / 不可接受的行为

- Harassment, insults, threats, or discriminatory jokes and language.
- Sexualized language or imagery, and unwelcome sexual attention.
- Publishing someone's private information without explicit permission.
- Deliberately disruptive behavior, spam, or bad-faith arguments.
- Dismissing accessibility, privacy, or security concerns without engaging with them.

- 骚扰、侮辱、威胁，以及歧视性玩笑或言论。
- 性化语言或图像，以及不受欢迎的性关注。
- 未经明确许可公开他人的私人信息。
- 故意扰乱讨论、刷屏或恶意争论。
- 对无障碍、隐私或安全关切不予理会、直接否定。

## Scope / 适用范围

This code applies to all project spaces: GitHub issues, pull requests, discussions,
commit messages, code review, and any other space where someone is representing the
project. It also applies when representing the project in public spaces.

本准则适用于所有项目空间：GitHub Issue、Pull Request、讨论、提交信息、代码审查，
以及任何代表项目发言的场合。

## Reporting / 如何报告

If you experience or witness unacceptable behavior:

1. Contact the maintainer [@salt-jar](https://github.com/salt-jar) through the public
   contact information on their GitHub profile. If no contact method is listed, open a
   minimal issue asking for a private channel — **without** details.
2. If the report also involves a security vulnerability, follow our
   [security policy](.github/SECURITY.md) instead.
3. For platform-level abuse, use GitHub's built-in **Report abuse** flow.

Reports will be reviewed as promptly as possible and handled as confidentially as the
situation allows. The maintainer will avoid conflicts of interest; if the report concerns
the maintainer, use GitHub's abuse reporting channel.

如果你经历或目睹了不可接受的行为：

1. 通过维护者 [@salt-jar](https://github.com/salt-jar) GitHub 主页上的公开联系方式联系；
   如果主页没有列出联系方式，可以开一个**不含细节**的最小 Issue 请求私下沟通。
   **不要**在公开 Issue 中写出敏感细节。
2. 如果同时涉及安全漏洞，请按[安全政策](.github/SECURITY.md)报告。
3. 平台层面的骚扰/滥用，请使用 GitHub 自带的 **Report abuse** 流程。

我们会在合理时间内处理，并在条件允许的范围内尽量保密。
若报告涉及维护者本人，请改用 GitHub 的滥用举报渠道。

## Enforcement / 处理方式

Depending on severity and history, the maintainer may:

1. **Correction** — a private or public explanation of why the behavior was inappropriate.
2. **Warning** — a warning with expectations for future behavior.
3. **Temporary restriction** — temporary loss of participation privileges.
4. **Permanent restriction** — permanent removal from project spaces.

Repeated or severe violations may skip directly to a longer restriction.
Enforcement decisions are made in good faith and focus on keeping the community safe.

根据严重程度和既往行为，维护者可能采取：

1. **纠正** —— 说明该行为为何不合适；
2. **警告** —— 明确后续期望；
3. **临时限制** —— 暂时失去参与权限；
4. **永久限制** —— 永久移出项目空间。

反复或严重违规可能直接进入更长期的限制。处理决定以善意和社区安全为出发点。
